# 顶层笔记本文档的子文档导航

## 变更记录

| 时间 | 说明 |
|------|------|
| 2026-09-02 | 去掉「引用文档归为子文档」「删除未引用子文档」；文档树辅助只保留定位 |
| 2026-08-31 | 导航植入按虚拟父子关系列举笔记本根文档；移除子文档索引与正文子文档导航记载 |

## 背景信息

思源开启 `fileTree.boxDocEnabled`（顶层笔记本文档）后，笔记本与其根文档共用同一个 ID，磁盘上为 `<boxID>.sy`。该文档是笔记本根层普通文档的**虚拟父文档**：子文档仍放在笔记本目录根下，**不会**进入 `<boxID>/<boxID>/`。

原先导航植入用「物理路径去 `.sy` 再拼前缀」查 SQL，并把「路径上的上一层 `.sy`」当作父文档。对笔记本根文档这会变成 `path LIKE '/<boxID>/%'`，根层 `/<docA>.sy` 对不上，面板有框但列表为空。

子文档索引（文末写入 `((id '标题'))`）不再维护，入口与配置一并去掉。定位到文档树仍保留，且不再挂在索引开关上。引用归为子文档、删除未引用子文档已移除。

## 当前方案

判定当前文档是顶层笔记本文档：文档 ID 等于笔记本 ID，或 `path` 为 `/`、`/<boxID>`、`/<boxID>.sy`。

查子文档仍**仅 SQL**（不在热路径调用 `listDocsByPath`）：

- 普通文档：`path LIKE '<父文件夹>/%'`
- 笔记本根文档：该笔记本内全部 `type='d'`，排除自身

父子判定用逻辑父路径：`/a/b/c.sy` 的父仍是 `/a/b.sy`；根层 `/x.sy` 的逻辑父是 `/<boxID>.sy`。直接子文档模式只显示一层；嵌套模式在同一套逻辑父关系上建树。

## 其他模块引用约束

- 展示向子文档列举继续默认 SQL；顶层笔记本文档不得按物理文件夹 `/<boxID>/` 探活。
- 不要假设根层文档的 `blocks.path` 带 `/<boxID>/` 前缀。
- 已移除的索引写入、正文子文档导航、引用归集、删除未引用不得再被导航或其他模块调用。

## 工程师测试验收方法

1. 开启顶层笔记本文档后打开笔记本：导航植入列出根层直接子文档，不是「暂无子文档」
2. 普通有子文档的文档：列举结果与改前一致
3. 无子文档的普通文档：仍显示空态，不弹 `listDocsByPath` 找不到文件
4. 设置页、面包屑、工具栏、命令中不再出现「补全子文档索引」；定位仍可用；归集 / 删除未引用已移除
