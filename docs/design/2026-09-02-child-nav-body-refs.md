## 背景信息

挂件方案不进正文，编辑体验与原生块不一致。需要导航出现在正文里，同时能和用户手写的文档引用分开管理：只增删自动植入的块。原先用大纲 DOM 注入把段落引用伪装成 h6，易闪烁、难维护；改为正文直接写成 H5 标题包裹引用，大纲原生收录。

## 当前方案

打开文档（及子文档新建/删除/移动）时，用 SQL 列出当前层子文档，再列出本文中带 `custom-fhelper-child-nav="1"` 的块。思源 `/api/query/sql` 无 `LIMIT` 时默认最多 64 行，相关查询须自带足够大的 `LIMIT`，否则子文档一多就只能看到前 64 个自动块，多出来的非当前层引用删不掉，也可能给已有块再补一份。

- 有子文档、没有对应自动块 → `appendBlock` 接到**文档末尾**，写入 `##### ((id '标题'))`，并打上 `custom-fhelper-child-nav` / `custom-fhelper-child-nav-target`
- 有自动块、没有对应子文档 → `deleteBlock` 只删带标记的块
- 已有自动块若仍是段落（或非 h5），同步时 `updateBlock` 升级为上述 H5 形式，保留块 id 与属性
- 用户手写引用没有该属性，不同步、不删除
- 不重排已有自动块；不再插入导航结束 `---`；打开时清掉旧的 `custom-fhelper-child-nav-end` 分隔线

正文块类型为五级标题（`NodeHeading` / `h5`），内容为指向子文档的块引用。官方大纲按标题层级收录，插件不再注入大纲 DOM、不再 patch `Outline.update`。

斜杠命令「新建子文档块」可手动创建子文档：选中命令后先清掉当前行的 `/` 提示，再把带 `custom-fhelper-child-nav` / `custom-fhelper-child-nav-target` 的 H5 引用写进**同一行**（`updateBlock` 原块，不另插一块），然后打开该子文档；自动同步不会再为同一子文档重复插入。

若先把别的文档上的自动导航块搬进本文，应留在当前页，点面包屑「定位到文档树」后面的按钮，把这些块对应的文档移为当前层子文档。切走再回来会先跑同步：目标还不是子文档时会删掉这些块。

若先删掉某些自动导航块、不要对应子文档，同样应留在当前页，点移动按钮后面的「删除没有文档块的子文档」：当前层里没有自动导航块的子文档会立刻 `removeDocByID` 删除（下级一并进入回收站），不弹确认框。只认带 `custom-fhelper-child-nav` 的块，手写引用不保护。切走再回来会先跑同步，缺的自动块会被补回，按钮就看不到待删项。移动按钮用思源 `iconMove`，删除按钮用 `iconTrashcan`。

查子文档仍仅 SQL；顶层笔记本文档仍按虚拟父子列举。不再使用 DOM 挂件、夹缝备注、文档属性 layout、拖动排序、大纲注入。

自动引用的外观由设置 → 通用 →「子文档导航植入」里的「子文档引用美化」（`docRefStyle.enabled`，默认关）控制，与「启用子文档导航植入」同一分组：植入负责增删/升级自动块，美化只负责显示。该分组还包含「隐藏新建子文档按钮」（配置仍为 `fileTree.hideNewSubDoc`），不再单设「文档树」分组。开启美化后在 `html.fhelper-child-nav-style` 下用样式表选 `[custom-fhelper-child-nav="1"]` 内的 `block-ref`，做成正文色、加粗、链接式下划线；图标按目标文档 `ial.icon` 写入独立样式表（`::before`），默认用设置里的文档图标。不改引用 span。手写引用不受这套选择器影响。旧的「全部文档引用打标」已停用。

## 其他模块引用约束

- 其它模块应按普通文档引用处理这些块；识别自动块只能看 `custom-fhelper-child-nav`，不要用 `refs` 表把手动引用当成自动块。
- 自动块正文形态为 H5 + 文档引用；不要再依赖插件大纲注入 DOM。
- 不要给自动引用内部 span 写 `style` / `data-fhelper-icon` 一类标记，会进块属性。
- 「子文档引用美化」只改自动导航引用外观；手写引用与主题文档链接样式互不影响。
- MCP / `read_note` 会读到这些引用（含 H5 语法），这是预期。
- 热路径仍禁止对可能无文件夹的路径调用 `listDocsByPath`。
- 查自动块与子文档的 SQL 必须自带 `LIMIT`；思源接口默认 64 行。
- 面包屑「删除没有文档块的子文档」只根据自动导航块判断，不要把手写引用或 `refs` 表当成「有文档块」。

## 工程师测试验收方法

1. 缺的自动引用以 H5 形式出现在文档末尾，不夹进 YAML，也不再写导航结束 `---`。
2. 已有自动引用不被挪到文首或文末；子文档没了才删对应自动块。
3. 新建子文档后父文档末尾出现对应自动引用；删除子文档后对应自动块消失。
4. 用户手写的文档引用不被删除、不重复再插一份自动块（若该子文档已有自动块则不再插）。
5. 顶层笔记本文档仍可列出根层子文档。
6. 大纲中这些自动引用作为原生 h5 标题出现；点击跳到正文对应块。关闭植入后不再增删，已有 H5 块仍留在正文/大纲。
7. 旧段落式自动块再次打开文档后升级为 H5，导航标记仍在。
8. 开启「子文档引用美化」后，自动引用：正文色、加粗、链接式下划线、左侧文档图标；手写文档引用仍是原来的样子。
9. 关闭该开关后自动引用恢复官方样式，引用块仍在正文里。
10. 在自动引用所在行回车：新段落正常，引用旁不应出现 `{: style="…"}` 一类属性泄漏。
11. 关闭「子文档导航植入」后不再增删自动块；若美化仍开，已有自动引用继续用该外观。
12. `/` 打开斜杠菜单时「新建子文档块」在最顶；选中后斜杠提示消失，**同一行**变成带导航标记的 H5 引用（不另起一块、不留下 `/`），并打开新子文档；自动同步不重复插入。
13. 约 100 个子文档时，把非当前层子文档的自动导航块移入本文，打开/刷新后应删掉该块，且不为已有子文档重复插入。
14. 把非当前层的自动导航块搬进本文后，**不切页面**，点面包屑定位按钮后的「根据文档块移动文档」：对应文档成为当前层子文档，原块保留；切走再回来则块会被删。
15. 删掉若干自动导航块后**不切页面**，点「删除没有文档块的子文档」：不弹确认框，对应当前层子文档（及下级）直接删除，已有导航块的子文档保留。切走再回来则缺的块会被补回，按钮提示没有可删除项。手写文档引用不阻止删除。

## 其他说明

旧挂件若仍留在编辑器 DOM，打开文档时会清掉。文档上旧的 `custom-fhelper-child-nav-layout` 不再读取。不再维护大纲注入相关常量、Observer 与 CSS。
